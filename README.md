НИЗКОУРОВНЕВЫЙ АСИНХРОННЫЙ СЕРВЕР КОНСОЛЬНОГО ЧАТА НА ГЕНЕРАТОРАХ БЕЗ ASYNCIO

Этот проект был чем-то типа испытательного полигона для меня. Поскольку я изучил асинхронность как подход к программированию, мне стало интересно, смогу ли я сделать такую простую вещь как консольный чат, но асинхронный и без asyncio. Оказалось довольно просто.

Клиент здесь довольно топорный и ничего особенного в нем нет - обычный двухпоточный клиент, один поток принимает сообщения, а другой их отправляет, не было интересно с этим заморачиваться.

А вот сервер сделан интересно - для асинхронной работы он использует генераторы и select.

Как это работает:
На каждый сокет (кроме серверного, там только чтение) создается пара генераторов, reader и writer. Генератор бесконечен и yield происходит прямо перед блокирующей операцией чтения или записи в сокет, что позволяет нам вернуться только тогда, когда сокет будет готов к чтению/записи. Это мы узнаем с помощью select, проверяющий готовые к чтению/записи сокеты. Дальше мы просто приступаем их к немедленному выполнению, поскольку уверены в неблокирующих чтении/записи.
Принятие подключений сервером тоже реализовано через генератор, в который мы возвращаемся при каждой готовности сокета сервера к чтению, то есть при наличии нового подключения.

В чем асинхронность?
В том, что мы создаем подобие event_loop, который планирует задачи к выполнению так, чтобы мы не блокировались на них, а только приступали по готовности. Корутинами являются наши генераторы, а yield тут выступает подобием await, с которым мы выходим наружу из корутины.

Использованные библиотеки (помимо стандартных):
